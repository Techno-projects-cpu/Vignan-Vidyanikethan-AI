Cookies
& local storage.

Six keys, all first-party, none of them for advertising. This page lists what each one is for and how to remove it.

Last updated 27 October 2026

01 / The short version

This site sets no advertising cookies and no third-party tracking cookies. It uses one session cookie for signing in, and it keeps your work in your own browser's local storage so that the app still opens offline. Nothing in that storage is transmitted anywhere unless a feature you choose sends it — an AI provider you configured, or the search fallback.

02 / The session cookie

vv_session — set by this site only when you sign in to an account. It is HttpOnly (page scripts cannot read it), SameSite=Lax (it is not sent on cross-site posts, which is part of the CSRF defence) and Secure on HTTPS deployments. It expires when you sign out, when it times out, or when the server session ends. Without it you are still a guest: every study feature works, only syncing and the social layer need it.

03 / Local storage keys

  • vignan-chat — your conversations, kept on this device so a reload does not lose them. Deleted by Delete all local data.
  • vignan-settings — theme, font, motion and provider choices, including a provider key if you typed one. The key never leaves this browser except to the provider you picked.
  • vignan-progress — chapters read, cards due, quiz scores, streak. Exported to Export data as JSON.
  • vignan-books — the text you imported. It stays here; it is never uploaded.
  • vignan-social-cache — a short-lived copy of friend and leaderboard lists so the board does not flash empty. Refresh replaces it.
  • vignan-install — one flag saying the install prompt was already offered, and service-worker cache names, which is how offline mode works.

04 / Caches and offline mode

The service worker keeps a versioned cache of the app's own files — pages, styles, scripts, fonts and the painted backgrounds — so the site opens on a weak connection. A new release installs a new cache and deletes the old one on activation; a cache is never shared with another origin. Images and sounds are all local files: no CDN asset is requested, which is why this list has no third parties in it.

05 / What other people see

Your hosting provider sees ordinary request metadata (IP address, user agent, timestamps) for security and diagnostics. If a search fallback is on, your query is sent to Wikipedia and DuckDuckGo; if an AI provider is configured, the question is sent there. Those are requests, not cookies set by us, and they are described in the privacy policy and the sub-processor list.

06 / How to remove it

In the app: Settings → Delete all local data clears the app's own keys. To remove the cache as well, use your browser's site-data controls (in Chrome: Settings → Privacy → Third-party cookies → See all site data; in Safari: Settings → Privacy → Manage Website Data). Signing out ends the session cookie. Clearing site data also deletes your API keys and imported books, and that cannot be undone.
