& local storage.

First-party cookies, browser databases and offline caches: what they store and how to remove them.

Last updated 27 October 2026

01 / The short version

This site sets no advertising cookies and no third-party tracking cookies. It uses session and request-security cookies, and it keeps your study work in your own browser's IndexedDB and local storage so that the app still opens offline. Nothing in that storage is transmitted anywhere unless a feature you choose sends it — an AI provider you configured, or the search fallback.

02 / Login and request-security cookies

vignan_session — set by this site only when you sign in to an account. It is HttpOnly (page scripts cannot read it), SameSite=Lax (it is not sent on cross-site posts, which is part of the CSRF defence) and Secure on HTTPS deployments. It expires when you sign out, when it times out, or when the server session ends. On HTTPS science-fair preview hosts, this cookie uses SameSite=None; Secure; Partitioned so embedded login can work. Without it you remain a guest; account progress and social features need sign-in.

vignan_csrf is a request-security token, readable by the app so it can attach it to account changes. It normally uses SameSite=Strict, or None with Secure and Partitioned on preview hosts. It may be set before sign-in and is not an authentication cookie. Both cookies have a server-configured lifetime.

vignan_admin is a separate HttpOnly operator-console session, set only after operator authentication. It is not a student session.

03 / Browser databases and preferences

vignan-study-ai is the IndexedDB database. Its stores are books, chunks, settings, messages and results. They hold imported text, search indexes, private AI conversations, settings (including keys you enter) and study results. Decks and other study settings also live in this database. If storage is unavailable, the app may use temporary in-memory storage.

Local storage holds preferences and small flags, including vignan.theme, vignan.style, vignan.style.school, vignan.firstRun.v3 and vignan.code.read. Session storage may hold tab-only entry state. This is a description of the storage categories, not a promise of exactly six keys.

On-device model downloads use separate browser caches. Student keys may be sent to the selected provider or through the site's proxy when used; operator keys remain on the server. Private AI chats are not account-synced, but messages you send to people in the social Chat feature are server-stored.

04 / Caches and offline mode

The service worker keeps a versioned cache of the app's own files — pages, styles, scripts, fonts and the painted backgrounds — so the site opens on a weak connection. A new release installs a new cache and deletes the old one on activation; a cache is never shared with another origin. Images and sounds are all local files: no CDN asset is requested, which is why this list has no third parties in it.

05 / What other people see

Your hosting provider sees ordinary request metadata (IP address, user agent, timestamps) for security and diagnostics. If a search fallback is on, your query is sent to Wikipedia and DuckDuckGo; if an AI provider is configured, the question is sent there. Those are requests, not cookies set by us, and they are described in the privacy policy and the sub-processor list.

06 / How to remove it

In the app: Settings → Delete all local data clears the main study database and resets study settings. It is not a guarantee that every preference flag, cookie or downloaded model cache is removed. To remove the cache as well, use your browser's site-data controls (in Chrome: Settings → Privacy → Third-party cookies → See all site data; in Safari: Settings → Privacy → Manage Website Data). Signing out ends the session cookie. Clearing site data also deletes your API keys and imported books, and that cannot be undone.
