THE SMALL PRINT / 03

Security
& trust.

What protects your work, what this project deliberately does not collect, and how to tell us if something is wrong.

Last updated 29 October 2026

01 / The short version

Vignan Vidyanikethan AI is a student-built study project for the INSPIRE-MANAK science fair, run on a free hosting tier with a free database tier. It is built to keep as much as possible on your own device: books, chats, decks, quiz results and settings stay in your browser unless a feature you choose sends them elsewhere. There are no advertising trackers, no third-party analytics and no data brokers. This page explains the protections that exist and, just as honestly, the ones a free project cannot promise.

02 / How your data is protected

Traffic between your browser and the site is encrypted in transit (HTTPS). The app sends strict security headers: a Content Security Policy that blocks outside scripts, MIME sniffing protection, a narrow permissions policy, and a same-origin resource policy. The page is deliberately allowed to be embedded in the science-fair preview, so framing is not blocked; instead, every change to your account requires a CSRF token and a same-origin request. Session cookies are HttpOnly, SameSite and Secure where the deployment allows it, so page scripts cannot read them.

Changes to your account — sign-in, progress, friends, chat — require a same-origin request with a CSRF token, and the server rejects cross-site form posts and non-JSON mutations. Password handling is delegated to the configured account backend, which stores hashes with a deliberate, slow key-derivation function; the app never stores or returns your password. Sign-in, registration, progress, search, link reading and AI proxy calls are rate-limited per address.

Your API keys live in this browser's storage, are excluded from the app's JSON export and from account records, and are only sent to the provider you selected (directly, or through this site's proxy when you choose the school key order). Anyone with access to your browser profile can still read them, so use your own free-tier keys and revoke them if a device is shared or lost.

03 / What is deliberately not collected

No advertising identifiers, no third-party analytics, no cross-site tracking pixels, no fingerprinting scripts, no selling or sharing of data with data brokers, and no upload of your textbooks. Registration stores an age band rather than an exact age, and the public leaderboard shows a username and study statistics only — never age band or gender. Guest use creates no account at all.

04 / Limits you should know about

This is a school project on a free tier, not a bank. Hosting and database providers may keep ordinary request metadata such as IP addresses for security and diagnostics, and can be unavailable at times. The project cannot promise a formal audit, a specific incident-response time, or a guarantee that no bug exists. Links you ask the app to read are fetched by the server, so only request public pages. Never paste passwords, OTPs, ID numbers or other private details into the question box.

If a connected AI provider is enabled, the parts of a question needed to answer it are sent to that provider under its own terms. Search fallback sends your query to Wikipedia and DuckDuckGo. Both are described in the privacy policy; switch them off if you do not want that.

05 / How the project's own keys are kept

This is a school project with no budget, so the AI keys come from free tiers. That makes key handling the most likely way for something to go wrong, and it is treated that way. No key is written into the code, the repository or the browser bundle: the server reads each one from its environment on Render, and the browser never receives a secret.

Every release runs a scanner over the tracked files that knows the shape of a Supabase, Google, OpenAI, GitHub, Slack, Cloudflare and AWS credential, and fails the build if one appears. If a key ever does reach the repository, it is treated as burned: it is revoked with the provider and replaced rather than quietly deleted, because a value that reached Git stays in its history. Students may add their own key in Settings, where it is stored only in their own browser.

06 / Reporting a security problem

If you find a vulnerability, please report it privately to the project operator — the student, the teacher in charge, or the school office of Vignan Vidyanikethan English Medium High School — rather than publishing it or using it to access other people's data. A useful report includes the page or endpoint, what you expected, what happened, and the smallest steps that reproduce it. Please do not run automated scanning against the live site, do not attempt to access accounts that are not yours, and do not test with real personal data.

Good-faith reports about this project are welcome and will not be treated as attacks, as long as they stay within those limits and India's applicable law. Machine-readable contact and policy details are published at /.well-known/security.txt.

07 / Your rights and how to exercise them

Under India's Digital Personal Data Protection Act, 2023 and similar laws elsewhere, you can ask what personal data is held about you, ask for it to be corrected, and ask for it to be erased. For data in your own browser, you can do this yourself: Settings, then Export data gives you a JSON copy, and Delete all local data removes it (then clear the site data in your browser to remove the offline cache too). For account records on the server, ask the project operator; the app does not currently offer self-service account deletion.

08 / Staying safe while using it

Use a passphrase rather than a short password, never reuse a school or personal password here, sign out on shared devices, and delete local data when you finish. Check a cited page before you rely on an answer — every line in a cited answer points at the page it came from. Treat outside web results as unverified. If something in an answer looks wrong or unsafe, tell your teacher; that feedback is how the project improves.
