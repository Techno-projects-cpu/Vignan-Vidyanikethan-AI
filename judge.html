01 / What it is — and what it is not

Every school AI project this year will be "an AI that answers questions". The interesting question is why anyone should believe the answer. This project's answer is a constraint: the AI may only answer from pages the student actually has, and every sentence it claims to be sourced must carry a book, chapter and page. When the saved pages cannot support a question, the app says so and offers a different route rather than inventing one.

Built on free tiers only: Render for hosting, GitHub for the code, Supabase for accounts, and the student's own free AI keys. No paid dependency, no shared key, no advertising, no analytics.

For students aiming past school exams, the app also rehearses the shape of JEE, NEET and AP EAPCET papers — question counts, time per question and marking, with negative totals reported honestly. Those patterns are public facts from the exam bodies; the questions themselves are still written only from the student's own pages, and no past papers, coaching material or textbook scans are shipped or downloaded.

02 / Test one: the citation

This is the claim that matters most, so test it first, in about twenty seconds.

  1. Add a page you can open by handUse Add book with a PDF, a photo of a page, or a few paragraphs of text. Any page works — even one you typed yourself for this test.
  2. Ask something that is only in that pagePick a sentence with a number, a date or a term in it, and ask about that.
  3. Read the citation under the answerIt names the file and the page number, and quotes the sentence it used.
  4. Open the page and check itThe quoted sentence should be there, on that page. If it is not, that is a bug and we want to hear about it.

"It won't answer from nothing. If the book doesn't cover it, it says so — and only then does it offer a labelled web search instead."

03 / Test two: pull the plug

04 / Updates ask first

A new version never replaces itself mid-lesson. It installs, then waits. A banner offers Update now or Later, and nothing is uploaded either way — books, decks and chats stay in the browser.

"You can see the banner, the release number and the offline readiness in Settings. The student stays in control of the tool."

05 / Questions a judge usually asks

Isn't this just a wrapper around ChatGPT?
Wrapper is fair, if it stops there. The work is the constraint layer: a page-level retrieval index that runs in the browser, an answer path that is refused when evidence is thin, a citation that has to name a page, an offline fallback that degrades in a defined order, and a local model option so it can run with no cloud at all. Plenty of wrappers answer anything; this one declines when it cannot show its working.
Why not train your own model?
Because a school project cannot train a model that beats the ones already available, and pretending otherwise would waste the effort. The scarce thing here is not another model — it is a trustworthy study loop around the models that exist.
What if the provider is down or the key runs out?
Keys rotate automatically, a rate-limited key is retired for a minute, and the app falls back through several providers. If every key fails, the answer comes from the student's own pages instead of failing outright.
Is student data being sold or trained on?
There is no analytics, no advertising identifier and no data broker. Books, chats and results stay in the browser; only the text needed for one answer is sent to the provider that writes it. The details are in the privacy policy, written in plain language.
Other free AI tutors already exist. Why build another?
Because reading them was the best part of building this, and two different projects share the name Eklavya, so both should be named properly. The funded one, eklavya.io, is built by the team behind Apni Pathshala with Malpani Ventures: free, no ads, no credit card, covering CBSE/NCERT, JEE, NEET and eight state boards. It is the standard in this space and this project does not claim to beat it. The other is an independent weekend hackathon repository that happens to carry the same name, credited in OPEN_SOURCE_CREDITS.md; the idea of a viva that asks you to explain and then names the misconception came from reading that code, and was rewritten here in our own rules because that repository publishes no licence. One honest local reason to build at all: eklavya.io lists Andhra Pradesh and Telangana as "on our list", so a student in Guntur is not served yet. Upload your own school book here and every answer names a page of it, and the whole study loop — quizzes, flashcards, exam mocks, a viva — keeps working with the network off.
Was this code written by AI?
Partly, and it says so here rather than waiting to be asked. The code in this repository was written with an AI coding agent (Arena Agent Mode) working under the student's direction: the student chose the scope, rejected ideas, decided what would be built and what would not, and the agent wrote the code and the tests. That is the same way the independent open-source Eklavya repository (not eklavya.io, the funded product) was built — its own project log refers to "the agent" as the thing that had no microphone — and it is how a lot of software will be written from now on. The reason to trust this one is not who typed the code. It is that every claim on this page can be re-run: 471 tests, a service worker simulation with the network off, a secret scanner, and an offline coverage check that fails the build when a feature would break without Wi-Fi. Read the tests, then break them.
The start screen looks like another tutor's. Did you copy it?
The pattern, yes; the work, no. Opening with a question and a few ready sentences instead of an empty box is taken from eklavya.io, whose public pages were read closely — that is credited in OPEN_SOURCE_CREDITS.md along with two smaller ideas: each language shown as a character in its own script, and an unbuilt feature marked "coming soon" instead of offering a button that fails. Their source is not published, so not a line of it could have been copied. The sentences here, where each one leads, the CSS and the rule that every sentence must be answerable from a cited page are this project's own — and one of the five sentences, the viva, only exists because a different open-source project published its rules.
What stops it from making up a page number?
Two things: the answer refuses the built-in fallback when retrieval found evidence, and the citation shown is assembled from the retrieved chunk itself, not from the model's sentence. That is also why we ask you to open the page and check.

06 / Honest limitations

Checked against ordinary questions, not chosen ones: thirty-one questions a visitor actually asks — why does a body float in water, what is pH, how does a transformer work, explain the water cycle — are asked of the built-in starter pages on every build. Each one must be answered from a page that carries the question's own topic. A page that merely shares filler words fails the build, which is how two real defects were found and fixed: a question about photosynthesis answered from a chemistry page about "matter", and a question about a transformer answered from a chapter about "work". The list is in tests/answer-bench.test.mjs, and it is a list of questions, so it can be added to.

Checked by machine, every time: 471 automated tests; a service worker simulation that installs the real worker, turns the network off and asks for every file of the release; a scanner that fails the build if a credential appears in the repository; and a coverage test that fails if any module, script or stylesheet the app loads is missing from the offline cache.

Not proven here, and stated plainly: speech has not been tested on a real phone with a real microphone in this build, so treat the voice buttons as best-effort; there has been no professional security audit; the app has not been load-tested with a whole school; and the account backend is only known to be healthy when the /setup page shows all three secrets as set. The leaderboard is practice only — scores start in the browser and a determined student could edit them.

  • No textbook is bundledNo publisher has given permission, so the app never ships NCERT or SCERT text. Instead it ships a starter shelf written for this project: four subject books that work exactly like an uploaded book and can be removed in one click. Student uploads are searched first, and the real textbook is added by the student.
  • Free hosting sleepsAfter a quiet period the Render service takes about half a minute to wake. During the demo, load the page once before you start.
  • Speech is the browser's, not oursReading aloud uses whatever voice the device has, so it sounds different on every phone, and a spoken answer needs a connection in most browsers. Both buttons say so instead of failing silently.
  • The local model is optional and heavyRunning a model in the browser needs a capable device and a large one-time download. It exists so the app can work with no cloud, not as the default.
  • Offline means your own pagesWith the network off, answers come from saved material. It is a study fallback, not a search engine in your pocket.
  • One student, no auditThere has been no professional security audit. The protections in place, and what is deliberately not collected, are listed on the security page.
